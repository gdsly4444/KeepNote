# KeepNote 编码规范

状态：草案 v0.3  
日期：2026-11-15

逻辑和界面可以完全隔开。层与层、以及每一层内部的模块，都靠单向依赖和窄的公开入口保持高内聚、低耦合。渲染进程拿不到磁盘和密钥，主进程拿不到组件和编辑器实例。一个模块的内部改动，不需要改到另一个模块的调用方。

## 1. 四块代码

| 块 | 目录 | 可以依赖 | 职责 |
| --- | --- | --- | --- |
| 契约 | `shared` | 无业务代码，无 Node，无 React | 命令、查询、事件、文档 DTO |
| 逻辑 | `main` | `shared`、Node、Electron 主进程 API | 库、索引、命令、Agent 循环、模型请求 |
| 桥 | `preload` | `shared`、Electron preload API | 把契约实现成渲染进程能调用的对象 |
| 界面 | `renderer` | `shared`、React、TipTap、CodeMirror | 绘制、输入、动效、编辑器视图 |

依赖方向：

```text
renderer  →  shared  ←  main
              ↑
           preload
```

`renderer` 不引用 `main`。`main` 不引用 `renderer`。`preload` 不写业务规则。`shared` 不引用另外三块。

模块 1 落地时用 ESLint 的目录边界把这四条写成可失败的检查。层内「只从模块入口引用」同样写成检查。人工复查不能代替这两条检查。

## 2. 内聚和耦合

层与层、层内的模块与模块，用同一组原则。

### 2.1 一个模块只有一个变化理由

模块里的每个文件都为这一件事服务。出现第二个变化理由，就拆成另一个模块。

逻辑层：

| 模块 | 只负责 |
| --- | --- |
| 库 | Markdown 怎么读写、怎么监听 |
| 索引 | 标题、文件名和「今天改过」怎么查 |
| 命令 | 一条用户意图调用哪些能力 |
| Agent | 这一轮读哪些片段、何时再问模型、差异何时交还 |
| 模型客户端 | 消息怎么流式发出去、怎么读回来 |

界面层：

| 模块 | 只负责 |
| --- | --- |
| 视觉令牌 | 字、色、间距、动效曲线 |
| 契约客户端 | 组件怎么拿到命令、查询和事件 |
| 文档页 | 一种文档类型怎么排、怎么编辑 |
| 命令行 | 输入、补全列表和回显 |
| 侧栏 | 导航或上下文里的列表和选择 |
| 壳 | 把栏、命令行和文档页摆在一起，管焦点和展开 |

文档页不计算今天改过哪些文件。索引不决定 `log` 写进哪一节。壳不解析 Markdown。

### 2.2 只依赖对方的公开入口

每个模块有一个入口文件，只导出接口和纯数据。其他模块引用这个入口，不引用它内部的文件。

接口按调用方的需要拆短。库的读取接口不包含保存，保存接口不包含检索。Agent 依赖读取接口，不因此获得写文件的能力。

对象在组合根里创建一次，经构造函数传进去。模块自己不 `new` 另一个模块的实现，也不去取全局单例。

### 2.3 依赖没有环

层的方向已经是 `renderer` 和 `main` 都只指向 `shared`。层内同样单向。

逻辑层：

```text
模型客户端
库
索引     → 库的只读接口
命令     → 库、索引
Agent    → 命令、库的只读接口、模型客户端
```

库不调用索引、命令或 Agent。索引不调用命令。Agent 不打开文件系统。模型客户端不知道笔记的结构。

界面层：

```text
视觉令牌
契约客户端
文档页   → 视觉令牌、契约客户端
命令行   → 视觉令牌、契约客户端
侧栏     → 视觉令牌、契约客户端
壳       → 文档页、命令行、侧栏的入口
```

文档页不引用命令行的内部组件。命令行不引用某种文档页的编辑器。壳只把它们的入口摆在一起。五种文档页互相不引用，共同需要的排版放在视觉令牌或文档页的公共入口里。

### 2.4 模块之间传递事实

跨过模块边界的是纯数据，或对方公开接口上的方法。不传递私有缓存、文件句柄、编辑器状态、锁。

索引需要路径和修改时间，不需要库内部的监听对象。Agent 需要读到的正文和大纲，不需要索引的倒排表。文档页需要契约里的文档数据，不需要命令登记表。

### 2.5 怎么检查

- 改一个模块的内部实现，其他模块的调用代码和测试不用改。
- 两个模块互相引用，或一个模块的内部文件出现在另一个模块里，耦合就过高。
- 入口导出了缓存、锁或框架对象，边界就漏了。
- 一次改动要同时打开两个没有调用关系的模块，先补一条公开接口，再改。

## 3. 契约

契约是两边唯一的共同语言。它只有类型和常量，没有函数实现，没有类实例。

三条通道：

| 通道 | 方向 | 内容 |
| --- | --- | --- |
| 命令 | 界面向逻辑 | 一次意图。`today`、`log`、`open`、`applyDiff` |
| 查询 | 界面向逻辑 | 一次读取。打开的库、一篇文档的正文、索引补全 |
| 事件 | 逻辑向界面 | 事实变化。文件已保存、索引更新、Agent 文本增量、一份待确认的差异 |

规则：

- 参数和返回值都是可结构化克隆的纯数据：字符串、数字、布尔、普通对象、数组。不传函数、类实例、`Editor`、DOM 节点、`fs` 句柄。
- 命令名和事件名集中在 `shared` 的一张表里。界面和主进程都从这张表取值，不手写字符串。
- 一个命令做一件事，输入和成功结果写在类型里。失败是契约里的错误值，带代码和人能读的原因，不靠抛出渲染进程里的异常来传业务失败。
- 界面发起命令后可以继续接收输入。完成、失败和取消都由事件或这条命令的结果表达。

`preload` 暴露一个对象，例如 `window.keepnote`。它的类型等于契约。渲染进程业务代码只依赖这个类型，测试时用同一个类型的假实现替换，不启动 Electron。

## 4. 逻辑层

主进程拥有事实：磁盘上的 Markdown、索引、命令是否成功、Agent 会话。

- 库、索引、命令登记、Agent 循环、模型客户端分成各自的模块。模块之间通过构造函数传入的接口协作，不互相引用具体实现文件。
- 命令登记是逻辑层的门面。侧栏点击、命令行和 Agent 工具都执行这里的命令，不另写一条写文件的路径。
- 会改文件的操作先产生差异数据。`applyDiff` 才写入。写入用原子替换，写完发出「已保存」事件。
- Agent 循环只通过命令和库的接口读笔记。它不知道当前有几个窗口，也不知道 TipTap 的文档结构。
- 密钥、模型流式解析留在主进程。`pi-ai` 只出现在模型客户端里。
- 主进程的单元测试不创建 `BrowserWindow`。

## 5. 界面层

渲染进程拥有呈现：滚动位置、焦点、动画、选区在屏幕上的样子、哪一栏是展开的。

- 组件按区域拆：壳、文档页、命令行、侧栏。文档页按类型再拆，共用壳的布局组件。
- 组件从钩子或上下文读取 `window.keepnote` 的类型，不直接调用 `window.keepnote` 散落在各处。测试替换这一处即可。
- 服务端状态从查询和事件来。组件可以保留一份只用于绘制的副本，副本的更新来自事件，不来自组件自己改磁盘。
- TipTap 和 CodeMirror 只存在于文档页。它们的编辑器实例不出组件。需要持久化时，文档页把 Markdown 字符串或契约里的差异交给命令。
- 视觉只用模块 2 的字体、颜色、间距和动效。组件不写一套私有色值。
- 界面测试不读真实文件夹。

## 6. 容易穿层的地方

这些地方按下面的切分做，隔离就还在。

| 场景 | 逻辑层拥有 | 界面层拥有 |
| --- | --- | --- |
| 一篇笔记 | 路径、类型、Markdown 正文、保存结果 | 排好的页面、插入符、滚动 |
| 工作记录 | 四节的正文、`log` 追加到哪一篇 | 日期和「在做」如何钉在页面上方 |
| 差异 | 按类型分组的旧文本和新文本 | 差异画在哪一段上，接受按钮的位置 |
| 补全 | 标题和文件名的候选 | 列表出现在命令行上方的动效 |
| 今天改过 | 按修改时间算出的路径列表 | 侧栏里怎么排列和接受 |

类型字段 `essay`、`journal`、`work`、`list`、`tech` 属于契约。某种类型用衬线还是等宽，属于界面。

## 7. 修改时怎么判断

一次改动只碰一边，说明隔离还在。

- 改版式、动效、快捷键的呈现：只改 `renderer`。
- 改保存方式、索引结构、模型提供者：只改 `main`。契约里的 DTO 不变时，界面不用改。
- 新增一种用户意图：先在 `shared` 加命令或事件，再在 `main` 实现，最后在 `renderer` 调用。不从组件直接写文件。

需要同时改 `main` 和 `renderer` 的内部实现才能完成一件界面上的事，就是穿层了。先把那件事收成契约上的一条命令或事件。

## 8. 写法

- TypeScript 严格模式。契约的公开类型不用 `any` 和 `object`。
- 边界上的类型手写，并写出字段含义。不把 TipTap 的 JSON、CodeMirror 的状态、或 Node 的 `Stats` 放进契约。
- 一个文件一个主要职责。逻辑模块的公开入口是它的接口，具体类不从包外引用。
- 名字用领域里的词：库、文档、命令、差异、工作记录。不用 `data`、`info`、`handle` 这种没有对象的名字。
- 异步操作接受取消。用户退出时主进程取消模型请求和未完成的写入准备。

## 9. 多平台

同一套代码在 macOS、Windows 和各类 Linux 上运行。界面只有一份。平台差异收进逻辑层的一个平台模块，其他模块面向它的接口，不读取 `process.platform`。

平台模块负责的差异：

| 事项 | 做法 |
| --- | --- |
| 路径 | 用 Node 的路径 API 拼接和比较。契约里的路径是普通字符串，由逻辑层规范化后再使用 |
| 换行 | 写入 Markdown 时使用 `\n`。读入时接受 `\r\n`，不把 `\r` 留在正文和差异里 |
| 文件名大小写 | 比较路径时不假定磁盘区分大小写。展示用用户原来的写法 |
| 监听文件 | 使用跨平台的监听实现。业务模块不调用某一系统专有的监听 API |
| 退出 | Windows 和 Linux 在最后一个窗口关闭时退出。macOS 关闭窗口后进程可以留着，但不再跑 Agent、不再改文件；用户明确退出后进程结束 |
| 快捷键 | 界面用「主修饰键」表达 Command 或 Ctrl。组件不写死某一个平台的按键名 |
| 字体 | 正文字体随安装包分发，不依赖系统里恰好有哪一款中文字体 |

界面不按平台复制三份组件。Chromium 负责合成、输入法和动效，所以版式、焦点和中文组字在三端走同一条路径。业务代码不调用某个系统的原生界面库来画文档页。

逻辑层的路径、换行和文件名比较要有测试。这些测试不依赖开发机是哪一个系统。

## 10. 禁止

- `renderer` 引用 `fs`、`path`、`child_process`、Electron 主进程模块，或任何 `main` 下的文件。
- `main` 引用 `react`、`react-dom`、TipTap、CodeMirror，或任何 `renderer` 下的文件。
- 把编辑器实例、组件 props 或回调函数放进 IPC。
- 在组件里拼接库内路径再假定主进程会照单读写。路径由逻辑层生成和检查。
- 为了省事让界面和逻辑共用一个可变单例。
- 在 `shared` 里写 IO、网络或框架代码。
- 引用另一个模块入口以外的文件。
- 层内出现循环依赖。
- 在组合根以外创建另一个模块的具体实现。
- 让一个模块为了方便去读另一个模块的私有缓存或编辑器状态。
- 在平台模块以外读取 `process.platform`，或按操作系统复制一套界面。
- 用字符串拼接 `/` 或 `\` 来组装库内路径。
- 把 `\r\n` 原样写回 Markdown。
