# KeepNote PRD

状态：草案 v0.3  
日期：2026-11-14  
范围：个人本地 Markdown 笔记工具的第一版产品定义

## 1. 一句话

KeepNote 是一个以阅读和写作为中心的本地 Markdown 笔记工具。笔记页是唯一的主舞台；终端式命令行和侧边栏是同一套笔记能力与 Agent 能力的两种入口。文档按用途分成不同类型，类型决定版式、主输入方式和周围界面。每个工作日有一篇工作记录，用来写下这一天在库里做了什么。界面必须在第一眼就显得精致，在连续使用中保持顺滑。

## 2. 要解决的问题

现有工具通常把三件事拆开，而且每一件都做得不完整：

- 笔记编辑器要么像代码编辑器，阅读时排版粗糙；要么像文档网站，写起来迟钝。
- 命令面板能跳转文件，但不能把「整理笔记、改写段落、建立链接」做成一套可复用的动作。
- Agent 聊天窗是贴在旁边的另一个应用，改完笔记不展示差异，和笔记本身脱节。
- 长文、日记、待办和技术记录共用同一个编辑器皮肤，用途不同，写起来和读起来却一样。
- 一天的工作散落在各个文件的修改时间里，没有一篇文档负责记下今天做了什么、产出在哪、还剩什么。

KeepNote 把这些收成一个表面：人在笔记上读写，需要速度时用命令行，需要浏览和确认时用侧边栏，需要帮忙时让 Agent 走同一套动作，并且每一次改动都看得见。打开不同类型的文档时，页面、字体和输入位置跟着用途一起变。

## 3. 产品定位

| 维度 | 定义 |
| --- | --- |
| 是什么 | 个人笔记工具。Markdown 文件是存储格式，类型决定页面如何呈现、从哪里输入。 |
| 为谁 | 长期写笔记、同时愿意用键盘和 Agent 整理知识的单人用户。第一版只服务自己。 |
| 主场 | 一篇打开的文档。每个工作日从今天的工作记录进入，再链到当天正在写的长文、清单和技术笔记。文件树、大纲、属性、命令行、Agent 都是附属表面，并随文档类型调整内容。 |
| 差异 | 命令行与侧边栏调用同一套命令；Agent 不是聊天窗，而是会提议笔记改动的操作者。 |
| 品质线 | 流畅和美观是上线条件，不是上线之后的润色项。达不到品质线的功能不做进主路径。 |

第一版明确不做：多人协作、云同步、移动端、插件市场、通用操作系统终端、任意代码执行。

## 4. 目标与非目标

### 4.1 目标

1. 打开一个本地文件夹，即可阅读、编辑、组织其中的 Markdown 笔记。
2. 每篇文档有明确类型。工作记录、长文、日记、清单、技术笔记在格式、主输入和界面上彼此可辨。
3. 每个工作日都有一篇工作记录。启动进入今天；人在其他文档里也可以把一条工作记回今天，并带上当时正在看的文档。
4. 长文的阅读态像一本排好的书页，编辑发生在同一页上。其他类型使用各自的主输入，不套用长文的书页。
5. 任意一个高频动作，既能从侧边栏点到，也能从命令行打到，结果和动效一致。主输入放在哪里，由文档类型决定。
6. Agent 能基于当前文档、选区和库内笔记完成整理与改写，改动以差异形式交给用户确认，并遵守该类型的结构。
7. 连续操作（切换笔记、切换类型、展开侧栏、呼出命令行、接受一处改写、从其他文档记一条工作）全程保持 60fps 的体感，没有布局跳动。

### 4.2 非目标

- 做一个通用 IDE 或嵌入真实 Shell。命令行只说笔记和 Agent 的语言。
- 让 Agent 在用户未确认时直接改写正文。
- 第一版支持富文本专有格式。对外交换格式只有 Markdown 与本地附件。
- 用功能数量换界面密度。主路径上的控件必须少，并且每个都有明确职责。

## 5. 体验原则

这些原则决定功能能不能进主界面。

1. **笔记优先。** 打开应用后，视线先落在正文，而不是落在工具栏。周围界面在用户开始写作时让位。
2. **一种动作，两种入口。** 侧边栏负责看见和选择，命令行负责说出和连续执行。两者调用同一个命令，产生同一种界面结果。
3. **Agent 是操作者，不是旁白。** 它的产出默认是可接受或拒绝的笔记改动、新建的笔记、或一条放进笔记的摘录。纯聊天只作为理解过程的附属。
4. **源码可及，但不是默认面貌。** 默认是排好的页面。用户可以切到 Markdown 源码，源码模式仍然遵守同一套间距、字体和动效。
5. **克制。** 颜色少，装饰少，动效短。精致来自排版、间距、层次和响应，不来自效果堆叠。
6. **键盘完整。** 鼠标可以完成的主路径，键盘也可以完成。命令行是键盘路径的中心，不是隐藏彩蛋。
7. **本地文件真实。** 磁盘上的 `.md` 就是笔记本身。应用不制造用户无法带走的私有正文格式。类型写在文件的 frontmatter 里，跟着文件走。
8. **类型决定表面。** 用途不同的文档使用不同的版式、主输入和侧栏内容。区分要在打开的一瞬间成立，靠版心、字体、密度和输入位置，不靠给每种类型换一套颜色。
9. **工作日有落点。** 今天做了什么写在今天的工作记录里。其他文档负责把事情写完，工作记录负责把这一天串起来。

## 6. 文档类型

库里的每篇文档有且只有一个类型。类型表达这篇文档的用处。用处一变，正文格式、主输入位置和周围界面一起变。

类型写在文件开头：

```yaml
---
type: essay
---
```

取值是 `work`（工作记录）、`essay`（长文）、`journal`（日记）、`list`（清单）、`tech`（技术笔记）。磁盘上仍然是 Markdown。打开文件时页面按类型切换。文件树上在名称旁标出类型，点开之前就能知道会进入哪一种页面。

新建时先选定类型。命令是 `new work`、`new essay`、`new journal`、`new list`、`new tech`，可以带标题。工作记录和日记按日期创建，不另取标题。导航侧栏的新建入口按这五类分开。

一瞥就要能分清类型。下面四项里，任意两种类型至少有三项不同：版心与密度、正文字体、主输入所在的位置、侧栏展示的内容。五种类型共用同一套颜色、动效和顶栏结构。

### 6.1 五种类型

| | 工作记录 | 长文 | 日记 | 清单 | 技术笔记 |
| --- | --- | --- | --- | --- | --- |
| 用处 | 一个工作日：在做什么、过程、产出、还剩什么 | 反复阅读的思考、文章、读书笔记 | 按天追加的个人文字 | 待办、收集、检查项 | 命令、配置、步骤、可复制的片段 |
| 格式 | 一天一个文件，固定四节：在做、记录、产出、留下 | 标题和段落构成的散文 | 一天一个文件，正文是按时间排列的条目 | 分组标题加任务项 | Markdown 源码；代码块、表格、有序步骤是主体 |
| 主输入 | 在任何文档里用 `log` 追加一条；「在做」在工作记录页上改 | 笔记页内所见即所得 | 打开日记后，命令行追加新的一条 | 行内编辑：回车新建，快捷键勾选 | 等宽的源码编辑 |
| 侧栏 | 近几天，以及今天改过、尚未记入的文档 | 大纲、反向链接、属性 | 近几天的日记 | 分组与完成状态 | 标题大纲和代码块列表 |
| 命令行 | `today`、`log`、`now`、`leave` | 打开、跳转、召唤 Agent | 打开日记后写下一条 | 过滤、归档、改写一行 | 打开、插入代码块、召唤 Agent |
| 版式 | 日期和「在做」固定在上方；时间列对齐；产出是文档名 | 窄栏、衬线、松行高、大页边 | 日期抬头，条目纵向堆叠，密度高于长文 | 紧凑行，勾选对齐，完成项降低对比 | 宽栏，无衬线正文，代码块占主要视觉重量 |

### 6.2 长文 `essay`

长文是未标明类型时打开的页面，也是品质线的基准页面。每个工作日从工作记录进入。

- 正文由段落、标题、引用、少量列表和图片组成。一级标题是文档标题。
- 打开时进入阅读。开始键入后，在同一页进入所见即所得。源码模式用来修正标记。
- 行长约 68 个西文字符。标题前后留白上大下小。正文字体用适合长文的衬线或人文无衬线。
- 上下文侧栏以大纲为主，其次是反向链接和属性。
- Agent 的改写保持散文结构。只有用户明确转换类型时，才把长文收成清单或技术笔记。

会议纪要、读书笔记、方案说明都用长文。它们之间的差别靠模板里的标题，不另做界面。模板可以预置「背景 / 决定 / 待办」这样的标题，页面仍然是长文。

### 6.3 工作记录 `work`

工作记录是每个工作日的家。一天从这里开始，人到其他文档里把事情写完，过程再记回这里。

- 路径按日期固定：`work/2026/11/2026-11-14.md`。一天一篇。
- 启动应用时打开今天的工作记录。同一天再次启动时，回到上次离开的文档；顶栏的「今天」始终回到这篇。
- 正文固定四节，顺序不变：在做、记录、产出、留下。创建时四节都在，标题保持这四个词。

```markdown
---
type: work
---

# 2026-11-14

## 在做

登录跳转

## 记录

- 10:12 修了登录跳转 [[登录跳转]]
- 15:40 把打包清单收成三组 [[本周打包]]

## 产出

- [[登录跳转]]
- [[本周打包]]

## 留下

- [ ] 补空状态
```

- **在做**是一句话，表示现在正在做的事。在工作记录页上直接改这一句，或在任何页面执行 `now 登录跳转`。
- **记录**是这一天的过程。每一条有时间、一句话，以及可选的文档链接。在任何文档里执行 `log 修了登录跳转`，都会追加到今天的工作记录。当时打开的文档附在这条上。提交后留在当前文档，命令行回显时间和写入结果。
- **产出**是今天要留下来的文档链接。上下文侧栏列出库里修改时间落在今天、尚未出现在产出中的文档。接受某一篇，才把它写进这一节。建议列表来自文件的修改时间，不另建一套活动数据库。
- **留下**是今天没做完的事，写法是任务项。`leave 补空状态` 追加一条。这一节可以在行内勾选。
- 页面向下滚动时，日期和「在做」留在页面上方。记录的时间列对齐，时间用等宽字体。产出显示文档名，点击按目标类型打开。留下只用清单的行距；在做、记录和产出保持工作记录自己的行距。
- 打开工作记录时，导航侧栏改为近几天的工作记录。上下文侧栏分两列内容：尚未记入的今天文档，以及已经写在产出里的文档。
- Agent 以一条记录或一整节为改写单位。请它收束今天时，它依据记录和产出提议一版「留下」，确认后才替换该节。

日记负责个人文字。工作过程、产出和未做完的事写在工作记录里。两者都按天成篇，页面、命令和侧栏各用各的。

### 6.4 日记 `journal`

日记用来按天追加个人文字。

- 路径按日期固定：`journal/2026/11/2026-11-14.md`。一天一篇。
- 每条以时间开头，下面是这段记录。新条目追加在文末。
- `diary` 打开或创建当天日记，并把插入符放进命令行。这条命令只在人已经决定写日记时使用。提交后写入新条目，页面滚到文末。
- 修改已有条目在笔记页内完成，编辑方式与长文相同，行高和页边用日记的密度。
- 打开日记时，导航侧栏改为近几天的日记。大纲退到上下文侧栏的次要位置。
- Agent 以一条日记为改写单位。摘要可以收成当天文末的一节，确认后写入。

### 6.5 清单 `list`

清单用来扫视和勾选。

- 结构是分组标题和任务项 `- [ ]`。出现在清单里的普通长段落显示为「未归类」，并提供收成任务项的动作。
- 阅读和编辑是同一个表面。每一行都可直接改：行尾回车产生下一项，Tab 调整层级，快捷键切换完成。
- 完成项留在原位并降低对比，直到执行归档。归档把完成项移到文末的「已完成」分组。
- 上下文侧栏是过滤：全部、未完成、已完成、某个分组。过滤只改变可见行，不改文件。
- 命令行执行清单命令，例如 `left`（只看未完成）、`done`、`archive`。
- Agent 返回的差异以任务项为单位。在清单里请它「整理」时，结果仍是分组和任务项。

### 6.6 技术笔记 `tech`

技术笔记里，标记本身是内容的一部分：命令、围栏、表格要能被直接看见和修改。

- 默认打开就是源码编辑。可以切出并排预览，源码保持可见。
- 版心宽于长文，以便一行放下命令和表格。
- 正文用无衬线，代码、命令和路径用等宽。代码块的背景和内边距重于段落。
- 上下文侧栏列出标题，以及每个代码块的语言和第一行。点击后滚动到该块。
- 命令行可以用 `fence sh` 在光标处插入对应语言的代码块。
- 从代码块复制时复制源码内容，不带围栏。
- Agent 的差异按源码行画在源码上。接受后文件仍是合法 Markdown。

### 6.7 输入落点

同一套命令系统，正文从哪里进入由类型决定。

| 类型 | 键入正文 | 结构化操作 | Agent 的差异画在 |
| --- | --- | --- | --- |
| 工作记录 | 任何页面用 `log` 追加记录；「在做」和「留下」在工作记录页上改 | 近几天，以及今天改过的文档 | 一条记录或一整节上 |
| 长文 | 笔记页 | 命令行、大纲 | 段落上 |
| 日记 | 打开日记后，新条目在命令行，旧条目在笔记页 | 近几天的日记 | 一条日记上 |
| 清单 | 清单的每一行 | 过滤侧栏、命令行 | 任务项上 |
| 技术笔记 | 源码页 | 代码块列表、命令行 | 源码行上 |

命令行的外观五种类型一致：等宽、提示符、历史。变的是它在这个类型里是主输入还是辅助输入。工作记录的 `log` 在任何页面都写回今天；日记要先打开当天日记再追加；长文和技术笔记里命令行负责跳转和召唤 Agent；清单里它负责过滤和归档。

### 6.8 类型的共同规则

- 顶栏结构、命令登记、动效曲线、差异确认、本地 Markdown，五种类型共用。
- `[[笔记名]]` 可以跨类型。打开目标时按目标的类型切换页面，切换动效与打开另一篇笔记相同。
- 转换类型使用 `type list` 这样的命令。转换先给出结构迁移预览：长文段落可以收成任务项，任务项可以展开成技术笔记中的列表或长文中的段落。确认后才改 frontmatter 和正文。
- 缺失或无法识别 `type` 的文件按长文打开，顶栏给出补上类型的入口。
- 模板只提供初始正文，不产生新的界面类型。

## 7. 界面结构

默认是三栏加一条命令行。中间栏永远最宽，两侧可以各自收起。外框五种类型相同，中间栏和侧栏内容按第 6 节切换。启动时中间栏是今天的工作记录。

```text
┌──────────────────────────────────────────────────────────┐
│  库名          当前笔记标题                 阅读 / 编辑   │
├────────────┬─────────────────────────────┬───────────────┤
│            │                             │               │
│  导航侧栏   │     当前类型的文档页          │   上下文侧栏   │
│  按类型新建 │                             │   随类型变化   │
│  文件树     │  工作记录 / 长文 / 日记 / …   │   大纲或过滤   │
│  标签       │                             │   属性        │
│            │                             │   Agent       │
│            │                             │               │
├────────────┴─────────────────────────────┴───────────────┤
│  ›  命令行：笔记命令、检索、对 Agent 说话                  │
└──────────────────────────────────────────────────────────┘
```

区域职责：

| 区域 | 职责 | 收起之后 |
| --- | --- | --- |
| 顶栏 | 标明位置和文档类型，提供「今天」和搜索。高度固定且薄。「今天」在五种类型里都在。 | 写作专注时淡出，留下笔记标题、类型，以及回到今天的入口。 |
| 导航侧栏 | 按类型新建、文件树、标签。打开工作记录时改为近几天的工作记录，打开日记时改为近几天的日记。负责「去哪里」。 | 命令行和快捷键仍可打开任意笔记。 |
| 文档页 | 按类型呈现阅读、编辑和 Agent 差异。唯一主舞台。 | 不可被其他面板覆盖成全屏聊天。 |
| 上下文侧栏 | 工作记录是今天改过的文档，长文是大纲与反向链接，日记是条目大纲，清单是过滤，技术笔记是大纲和代码块。Agent 会话共用。 | 对应跳转仍可从命令行完成。 |
| 命令行 | 终端样式的输入条。`log` 在任何页面都写回今天的工作记录。打开日记后，命令行是日记的主输入。 | 用快捷键唤回。 |

布局规则：

- 长文行宽约 68 个西文字符。日记略宽。工作记录比日记更紧，并留出时间列。清单行距更紧。技术笔记明显更宽。窗口变宽时增加页边，不把行拉满。
- 侧栏宽度可拖，拖动时正文不重排到难以阅读的宽度；低于可读宽度时，优先收起侧栏。
- 命令行默认是底栏一条。输入或查看历史时向上展开，覆盖在笔记页底部，不把正文顶走。
- 从任一入口触发的面板开合，使用同一套位移和淡入，避免有的面板滑入、有的面板硬切。

## 8. 双通道输入

命令行和侧边栏是同一命令系统的两种投影。

### 8.1 命令模型

每条能力登记为一个命令，包含：

- 名称与一句话说明
- 参数（可为空）
- 作用范围：整库、当前文档、当前选区、当前标题、当前任务项、当前日记条目
- 适用类型：全部，或仅某几种。在不适用的类型里，这条命令不出现在补全和侧栏中
- 执行结果：打开笔记、滚动到标题、插入文本、提出一处差异、打开面板
- 侧边栏上的对应控件（如果这个命令适合被看见）

界面只负责收集意图。意图进入命令系统后，再更新笔记、侧栏和命令回显。这样从点击、键盘、Agent 来的同一种操作，动画和结果一致。

### 8.2 命令行

视觉上借用终端：等宽字体、提示符、闪烁插入符、向上翻阅的历史。它不是系统 Shell。

输入分为三类，由内容决定，不要求用户先选模式：

| 输入 | 例子 | 结果 |
| --- | --- | --- |
| 笔记命令 | `today`、`log 修了登录跳转`、`open 周会`、`new list 打包` | 立刻执行，底栏回显一行结果。`log` 写回今天的工作记录，不切换当前文档 |
| 类型命令 | 在清单里输入 `left`；在技术笔记里输入 `fence sh` | 只在适用类型中执行 |
| 范围命令 | 选中段落后输入 `shorter` | 对当前类型的选区单位提出改写差异 |
| 对 Agent 说话 | `把这篇整理成决定和待办` | 在上下文侧栏展开本次会话，差异画在该类型对应的单位上 |

命令行交互要求：

- 键入时即时补全笔记名、标签、标题和命令名。补全列表出现在输入条上方，不挤占正文。
- 历史可搜索。上一次的 Agent 请求可以再执行。
- 多步操作可以连续敲，不必等面板动画结束才接收下一次输入。
- 回显保持短。成功是一行，失败说明原因和下一步，不弹出阻塞对话框。

### 8.3 侧边栏

侧边栏呈现适合「看见再选」的东西：

- 导航侧栏：按类型分开的新建、带类型标记的文件树、标签、最近编辑。打开工作记录时改为近几天的工作记录，打开日记时改为近几天的日记。
- 上下文侧栏：随类型显示今天改过的文档、大纲、反向链接、过滤、代码块列表或属性，以及共用的 Agent 会话。

侧边栏里的每个主要控件都对应一条命令。点击「今天」等于执行 `today`。把一篇今天改过的文档收进产出，等于在工作记录里接受那一条链接。点大纲里的标题等于执行跳转到该标题。这样两条通道不会各做一套逻辑。

Agent 会话放在上下文侧栏，而不是独立的全屏聊天。会话内容包括：用户这句话、Agent 读了哪些笔记、它准备做的改动。改动本身画在笔记页上。

### 8.4 通道对照

| 意图 | 命令行 | 侧边栏 |
| --- | --- | --- |
| 打开今天的工作记录 | `today` | 顶栏「今天」，或近几天里的今天 |
| 把当前工作记一笔 | `log 修了登录跳转` | 上下文侧栏里的「记到今天」 |
| 改今天的「在做」 | `now 登录跳转` | 工作记录页顶部的那一行 |
| 记一件还没做完的事 | `leave 补空状态` | 工作记录「留下」一节的行内输入 |
| 打开今日日记 | `diary` | 导航里日记分组的「今日」 |
| 新建某种文档 | `new essay 标题` | 导航里对应类型的新建 |
| 按名打开 | `open 周会` | 文件树点击 |
| 全文检索 | `find 定价` | 顶栏搜索 |
| 跳到标题 | `goto 决定` | 大纲点击 |
| 给笔记加标签 | `tag 项目/KeepNote` | 属性区添加标签 |
| 改写选区 | 选区后输入 `shorter` | 选区工具条「缩短」 |
| 让 Agent 整理全文 | 直接输入这句话 | 上下文侧栏的 Agent 输入框 |
| 接受改写 | `accept` | 差异卡片上的「接受」 |

选区工具条只在有选区时出现在长文、日记条目、工作记录的某一节和技术笔记里，贴在选区附近，包含少量高频动作：缩短、改写、译成中文、做成摘录。清单和「留下」的对应物是行上的勾选，不使用这段选区工具条。它是侧边栏通道在正文里的就地形态。

## 9. 文档文件

类型的版式和输入见第 6 节。这一节只写所有类型共用的文件规则。

### 9.1 库

- 用户选择一个本地文件夹作为库。库认识文件夹里的每一个文件，子文件夹是结构。`.md` 是笔记，会读出正文。其余文件留在库的名单里，供笔记链接，不读内容。
- 非 Markdown 在文件树里用对应的文件图标表示，不打开成文档页。图标晚于「认识文件」再做。图片拖进正文时，仍复制到附件目录并写成相对路径。
- 文档以类型、文件名和一级标题识别。没有一级标题时，用文件名作为显示标题。工作记录和日记以日期作为显示标题。
- 删除、重命名、移动都作用在真实文件上，并在命令行回显路径。类型转换会改写 frontmatter，并可能改写正文结构，因此必须先经过预览确认。

### 9.2 阅读

启动打开今天的工作记录，视线落在「在做」和已有记录上。长文打开即为阅读。日记打开后停在命令行，页内旧条目可阅读。清单和技术笔记打开即可操作，不另设一个书页阅读态。阅读能力本身五种类型都有：

- 标题、段落、列表、引用、代码、表格、图片、任务列表都有专门排版，而不是浏览器默认样式。
- 文内链接指向库内笔记时可以点击跳转；指向外链时明确标成外链。
- 长文和日记里的任务列表可在阅读时直接勾选；清单的勾选就是主操作；工作记录只在「留下」里勾选。勾选立即写回 Markdown。
- 代码块使用等宽字体并与正文区分。技术笔记里代码块是页面主体，其余类型里它不压过正文。
- 滚动位置按笔记记住。再次打开时回到离开的地方。

### 9.3 编辑

编辑发生在该类型的主输入上，规则见第 6.7 节。

- 长文和日记的已有条目默认所见即所得：用户看到排好的标题和段落，保存到磁盘的是 Markdown。
- 工作记录的「在做」和「留下」在页面上改，记录条目由 `log` 追加，已写入的条目可以在页面上改正。
- 清单在行内编辑任务项。技术笔记默认编辑源码。
- 长文、日记、工作记录和技术笔记提供源码与排版两种视图。切换时滚动位置和插入符保持在同一段。清单的行内编辑与文件中的任务列表是同一视图。
- 输入延迟必须不可感知。中文输入法组字期间不丢字、不跳动。
- 自动保存到本地文件。保存状态用顶栏一处极小的文字表达（已保存 / 保存中），不使用打断式提示。
- 图片从本地拖入时，复制进库的附件目录，并插入相对路径。第一版不做图床。

### 9.4 文档之间的关系

- `[[笔记名]]` 作为库内链接。不存在的目标显示为待创建，回车可创建。
- 上下文侧栏列出谁链接了当前笔记。
- `#标签` 写入正文即可出现在导航侧栏。标签是正文的一部分，不另存一套隐藏元数据作为事实来源。
- `today` 打开或创建今天的工作记录，模板写入类型、日期标题和空的四节。`diary` 打开或创建当天日记，模板写入类型、日期标题和第一条空白条目。

## 10. Agent

### 10.1 角色

Agent 读取用户允许它读的笔记，提出编辑、新建和摘录。它服务于当前这篇笔记，而不是打开一个与笔记无关的对话产品。

用户可以在三处召唤它，三者进入同一次会话：

- 命令行里的自然语言或范围命令
- 上下文侧栏的 Agent 输入框
- 选区工具条

### 10.2 第一版能力

| 能力 | 范围 | 用户看到什么 |
| --- | --- | --- |
| 解释与摘要 | 当前文档或选区 | 侧栏中的简短结果。长文和日记可插入文末；工作记录可收成「留下」的一版差异；清单可收成一个新分组 |
| 改写 | 当前类型的选区单位或全文 | 差异画在段落、工作记录的一条或一节、日记条目、任务项或源码行上，逐组接受或拒绝 |
| 结构化 | 当前文档 | 工作记录保持四节，只改节内内容；长文整理成标题与段落；清单整理成分组和任务项；技术笔记整理成步骤与代码块 |
| 新建文档 | 整库 | 先选定类型，预览标题和正文，确认后写入文件并按该类型打开 |
| 按库回答 | 检索到的若干文档 | 回答中每个依据都能点开原文档的对应位置，并按目标类型呈现 |
| 建立链接 | 当前文档 | 建议要连向的文档，确认后插入 `[[链接]]` |

Agent 提议的结构必须能放进当前类型。工作记录保持「在做、记录、产出、留下」四节都在。清单不接受一段无法对应到任务项的散文差异；技术笔记不接受把源码替换成纯排版页面的改动。用户要求的结果属于另一种类型时，Agent 改为提议 `type` 转换，并给出第 6.8 节中的迁移预览。工作记录和日记按日期成篇，不转换成其他类型；要把其中一段变成独立文档时，Agent 提议新建那篇文档，并在原处留下链接。

### 10.3 确认

- 凡是会改变文件内容的结果，先以差异出现在文档页上。
- 差异按该类型的单位分组：工作记录是一条记录或一整节，长文是段落，日记是条目，清单是任务项，技术笔记是源码行组。可以全部接受、全部放弃，或逐组决定。
- 放弃后正文回到原样，会话保留这次提议，方便改口再来。
- Agent 工作时，笔记页保持可滚动、可取消。进度写在侧栏会话里，不用全屏遮罩。
- 第一版不自动连续执行多步文件修改。一次请求对应一批待确认改动。

### 10.4 上下文边界

- 默认上下文是当前笔记和当前选区。
- 需要读其他笔记时，先检索再读取命中的笔记，并在会话里列出实际读过的文件。
- 不读取库外文件。
- 不执行系统命令，不访问网络，除非用户在后续版本里单独打开某个明确的连接器。第一版没有连接器。

### 10.5 失败

- 无法完成时，在会话里说明缺了什么（没有选区、没有命中笔记、模型不可用）。
- 命令行同步回显一行，并提供重试。
- 失败不改动任何文件。

## 11. 视觉与动效

美观和流畅在这里写成可检查的标准。评审时对照本节，而不是凭感觉说「再好看一点」。

### 11.1 视觉方向

整体是安静的纸面，命令行是纸面上的一条精确输入。五种类型共用这一套颜色，靠版心、字体和密度区分用途。

- 浅色：暖白纸色背景，墨色正文，一种低饱和强调色只用于插入符、链接、当前项和焦点。
- 深色：深墨背景，正文亮度低于纯白，避免发光感。强调色与浅色是同一色相。
- 侧栏比笔记页略深或略浅一个层级，用来区分平面，不用粗边框分割。
- 分割线能不用就不用，靠间距和背景差建立结构。
- 图标只做导航和状态，尺寸统一，线宽统一。不用插画和装饰性图形。

### 11.2 字体

- 长文和日记正文使用适合长文的衬线或人文无衬线。工作记录、清单和技术笔记正文使用中性无衬线。工作记录的时间用等宽字体。中西文在同一行里对齐，不出现中文突然变大或变小。
- 界面标签使用中性无衬线，字号小于正文，字重有规律：标题、控件、辅助信息三级就够。
- 命令行、代码、路径，以及技术笔记中的命令使用等宽字体。
- 字号阶梯全应用共用。行高和段间距按类型取该阶梯上的不同档：长文最松，日记次之，技术笔记中等，工作记录紧于日记，「在做」单独加大一档，清单最紧。某个面板不另起一套字号。
- 中文标点、西文空格、数字的混排按排版习惯处理，列表标记和标题编号对齐。

### 11.3 页面排版

- 每种类型的行长按第 6 节固定。长文行高偏松，段落间距大于行间距，标题前后留白上大下小。工作记录的日期和「在做」在滚动时保持可见，时间列宽度固定。清单以行距对齐勾选框。技术笔记让代码块宽于段落的视觉重量。
- 标题层级靠字号和留白区分，靠颜色区分的部分要少。
- 引用、代码、表格有自己的底色，和正文拉开一级，但不能抢正文。
- 选区颜色清晰且不脏。当前标题在大纲里有稳定的标记。
- 空库、空笔记、无搜索结果都有专门版式，和正式页面使用同一套字体与间距。

### 11.4 动效

动效用来说明空间关系：侧栏从哪边来，命令行从底部展开，差异从当前类型的改动单位里长出来。

| 场景 | 时长感 | 要求 |
| --- | --- | --- |
| 按钮、列表项悬停与按下 | 很短 | 颜色变化，不位移 |
| 侧栏展开收起、命令行展开 | 短 | 位移加淡入，正文宽度动画连续 |
| 笔记切换、类型转换后的页面更换 | 短 | 新页面淡入，版心变化连续，不左右乱滑 |
| 大纲跳转 | 极短 | 滚动平滑，目标标题有一次轻微高亮 |
| Agent 差异出现 | 短 | 从对应段落展开，不整页刷新 |
| 接受或拒绝差异 | 短 | 段落归位，周围文字让位平滑 |

规则：

- 所有面板使用同一条缓动曲线。
- 动画进行中继续接收输入，新的操作可以打断未完成的动画。
- 用户系统开启减少动态效果时，改为淡入或直接呈现，保留状态变化，去掉位移。
- 不用弹跳、视差、持续循环的装饰动画。插入符闪烁是命令行里唯一的循环动效。

### 11.5 状态

每个可交互表面都要设计这些状态，缺一则视为未完成：

- 默认、悬停、按下、焦点、禁用
- 加载、空、错误、成功回显
- 键盘焦点可见，且焦点样式与鼠标悬停样式不同
- 深色与浅色两套都要达到同一完成度

写作专注状态是一等状态：两侧收起，顶栏淡出，只留当前类型的文档页和一条唤回命令行的方式。工作记录的专注态保留命令行、日期和「在做」。日记的专注态保留命令行。进入和退出都可动画，也可瞬间完成。回到今天始终可用。

## 12. 性能预算

这些数字是体验要求，用来在实现阶段取舍，不是宣传口径。

| 项目 | 预算 |
| --- | --- |
| 键入到字形出现 | 一帧之内，中文输入法同样满足 |
| 命令行补全 | 一帧内给出本地结果 |
| 打开一篇普通文档（约几千字，任一类型） | 100 毫秒内可阅读或可输入 |
| 切换文档或类型表面 | 不出现白屏或布局跳动 |
| 侧栏拖拽、展开收起 | 动画期间保持 60fps |
| 滚动长文 | 持续 60fps |
| 保存 | 不阻塞输入 |
| 库内标题与文件名索引 | 万级笔记内，打开和按名跳转仍满足上面的打开预算 |

Agent 请求的网络时间不计入界面帧预算。界面在等待期间保持可操作，并提供取消。

## 13. 版本切片

品质线从第一片就生效。不做「先功能后美观」的中间版本。

### P0：可以每天工作，工作记录是这一天的家

- 打开本地库；五种类型可创建、可在文件树上辨认、打开时版式立刻不同
- 工作记录：启动打开今天；固定四节；`today`、`log`、`now`、`leave`；在其他文档里记一笔后留在原文档；侧栏列出今天改过、尚未记入的文档，接受后写入产出；近几天
- 长文：阅读、所见即所得编辑、源码模式、自动保存、大纲
- 日记：`diary` 按日期创建，命令行追加条目，近几天侧栏
- 清单：行内新建、勾选、完成态降对比
- 技术笔记：源码编辑、更宽版心、代码块列表
- 浅色与深色，共用的排版阶梯和动效语言，各类型取自己的行宽、字体和密度
- 底栏命令行：`today`、`log`、`diary`、`new <类型>`、检索标题与文件名、跳转标题
- 长文与技术笔记的写作专注；工作记录专注态保留命令行和「在做」；日记专注态保留命令行
- 空状态、错误回显、键盘焦点

验收：启动即进入今天的工作记录。在一篇技术笔记里执行两次 `log`，两条都出现在今天的记录里，并带上那篇技术笔记，当前页面不切换。把侧栏里今天改过的一篇长文收进产出。写下「在做」和一条「留下」。同一天用 `diary` 追加日记。勾选清单项。来回打开五种文档时，版心、字体和主输入位置都能立刻分清，全程没有明显掉帧、跳动和输入丢失。

### P1：两套入口合一，Agent 能改笔记

- 命令登记成一套，侧栏动作全部走命令；命令声明自己适用的类型
- 标签、库内链接、反向链接、长文模板（含会议纪要模板）
- 类型转换和结构迁移预览
- 选区工具条
- 清单过滤与归档；技术笔记的 `fence` 插入
- Agent：摘要、改写、按类型结构化、按类型新建
- 差异按工作记录的一条或一节、段落、日记条目、任务项、源码行组确认
- 命令行自然语言进入同一 Agent 会话

验收：同一条改写，从命令行、选区工具条、侧栏输入，得到同一张差异。在工作记录里收束今天时，差异落在「留下」；在清单里提出的差异是任务项；在技术笔记里是源码行。接受和拒绝后文件内容正确。把一篇长文转成清单时，先看到迁移预览，确认后类型和正文一起变。

### P2：库变成可检索的个人知识

- 全文检索
- Agent 按库回答，并跳回原文位置
- 建议链接
- 命令历史搜索，常用命令置顶
- 附件图片的稳定排版

### 明确后置

- 真实系统终端，以及任何超出库目录的命令执行
- 同步、协作、发布网页
- 插件
- 移动端
- 语音输入

后置项里，真实系统终端尤其不放进主界面。若未来要做，它是一个单独的、权限明确的面板，不和笔记命令行混用提示符。

## 14. 成功标准

第一版以使用感受为准，不以功能清单为准。

- 自己连续 14 天把 KeepNote 当作默认笔记入口。这 14 天每一天都有工作记录，记录里能看出当天做了什么，产出能点回当天写过的文档。长文、日记、清单也会在这 14 天里被用到。
- 打开一篇文档的第一眼就能说出它的类型，依据是版式和输入位置，而不是先去读 frontmatter。
- 阅读一篇旧的长文时，不需要切换到源码才能读懂结构。技术笔记则不需要离开源码才能改对命令。
- 每天的笔记操作里，命令行和侧边栏都会被用到，而且没有哪条高频动作只能在其中一个里完成。工作记录的追加以 `log` 为主，人不必先跳回今天才能记一笔。日记的追加以打开日记后的命令行为主。
- Agent 的改动里，多数是经过确认后接受的；差异的单位和当前类型一致。
- 任意主路径操作都可以指出它属于哪条命令、适用于哪些类型、动效是否符合第 11 节、是否落在第 12 节的预算里。

## 15. 风险

| 风险 | 表现 | 应对 |
| --- | --- | --- |
| 所见即所得与 Markdown 源码不一致 | 切换模式时内容变样、光标错位 | P0 就把模式切换当作主路径来做，用一组固定样例笔记回归 |
| 命令行做成迷你 Shell | 用户分不清能不能运行系统命令 | 提示符、补全和文案只呈现笔记命令与 Agent |
| Agent 会话抢走主舞台 | 界面变成聊天工具，笔记缩成预览 | 改动画在笔记页上，会话只留在上下文侧栏 |
| 视觉规范在赶功能时被绕过 | 某个面板用了另一套间距和颜色 | 新表面不满足第 11 节则不进入主路径 |
| 五种类型做成同一编辑器加一个标签 | 只有角标不同，版心、字体和输入位置相同 | P0 的验收要求来回打开五种文档时能立刻分清 |
| 工作记录写成另一篇日记 | 没有固定四节，`log` 必须先打开今天才能写入，产出靠人回忆 | P0 要求在其他文档里直接 `log`，侧栏能把今天改过的文档收进产出 |
| 动画拖累输入 | 打字或连按快捷键时掉帧 | 动画可被打断；输入路径不依赖动画结束 |

## 16. 待决问题

1. 所见即所得引擎自研还是基于现成编辑器。这个选择要在 P0 开始前定，因为它决定长文、日记和工作记录的排版上限和输入延迟。技术笔记的源码编辑可以单独选型。
2. 正文字体。长文衬线，以及工作记录、清单、技术笔记的无衬线，都需要用中英混排试读后再定。
3. Agent 的模型来源。第一版可以先接一个用户自己的 API Key，但密钥存放和离线时的界面要单独定。
4. 工作记录路径 `work/年/月/日期.md` 与日记路径 `journal/年/月/日期.md` 是否就按此固定。
5. 长文差异是否需要从段落再细到句子，等真实改写样例出来再定。工作记录、清单和技术笔记的单位不再加细。
6. 清单归档是移到文末分组，还是移到单独文件。第一版先用文末分组。
7. 「今天改过」按文件修改时间计算。只打开未改内容的文档要不要出现在建议里，第一版先不出现。

## 17. 名词

| 名词 | 含义 |
| --- | --- |
| 库 | 用户选定的本地文件夹。Markdown 是文档，其余文件也在名单里，但不是笔记。 |
| 类型 | 文档的用途。决定格式、主输入和界面。第一版是工作记录、长文、日记、清单、技术笔记。 |
| 工作记录 | 一个工作日的文档。固定为在做、记录、产出、留下。`today` 打开今天，`log` 从任何页面追加一条。 |
| 今天 | 本地日期对应的那篇工作记录。 |
| 文档页 | 中间的阅读和编辑表面，外观随类型变化。 |
| 主输入 | 这个类型里，正文首先从哪里键入。 |
| 命令 | 一条有名称、范围、适用类型和结果的笔记动作。点击和键入都变成命令。 |
| 命令行 | 底部终端样式的输入条，只接受笔记命令和给 Agent 的话。 |
| 差异 | Agent 或改写命令提议的正文改动，未接受前不写入文件。分组单位由类型决定。 |
| 专注 | 只留下当前类型文档页的界面状态。工作记录在此状态下保留命令行、日期和「在做」。日记保留命令行。 |
